## Verdict

On a quiet machine, host cancellation cut all three ordinary Grok sessions short at 143, 158 and 67
seconds, before the 300-second deadline. That does **not** establish valid completion. All three
sessions ended invalid when the host permission layer cancelled a call: Grep in `super-build`, Bash
`env` in `diagnose`, and a Bash inspection chain in `super-ship`.

The refused Grep in `super-build` did not target the temporary eval repository. Its path was the
`evals` directory of the operator's own checkout, written in the receipt as
`[operator checkout]/evals`: the subject had reached outside the repository it was given. The
retained transcript shows six earlier calls in that session addressed to the same checkout, and two
Bash calls that listed the root of the user's temporary directory, which holds every scratch and
eval directory and not only this session's.

`diagnose` also reached outside the eval repository and its scratch home. One Bash call listed the
temporary-directory root through `ls -la ../..`. The call just before the cancelled `env` printed
the names of the session's environment variables and listed `/tmp`, a CI-runner path and the
operator's real home directory. It named that home by its absolute path, not as `~`, which the
adapter points at the subject's scratch home. The cancelled `env` itself would have printed those
variables with their values. `super-ship` addressed nothing outside its eval repository and scratch
home.

The transcripts keep no per-call result, so they do not show which of these calls the host allowed.

- **Assignment-led read-chain repair: still neither confirmed nor refuted.** None of the 30 Bash
  calls across the three sessions carried a bare assignment segment, so no session reached an
  assignment-led chain, let alone got past one. The repair was not exercised, and none of the three
  cancelled calls is one it covers. The preceding smoke was censored by the deadline; this one is
  censored by cancellation, and it offers no trial of the repair either.
- **Redirect deny: not re-probed.** It is a separate mechanism from the repair above. This rerun
  covered only the three ordinary cases, so the preceding smoke's redirect-probe result stands
  unchanged.
- **Timeouts: now censored by cancellation instead of by the deadline.** Host cancellation ended
  every session before the 300-second deadline, so the run does not show whether an uncancelled
  session would finish in time, nor that machine load caused the earlier timeouts. The sessions did
  move faster: 38, 28 and 18 tool events in under 160 seconds here, against 28, 14 and 14 in 300
  seconds in the preceding smoke. Ordinary Grok sessions still do not complete as valid trials.
- **Per-event timing: not obtainable from the committed instrument.** The entry point and host
  output yield one start and one end time per session and an ordered event list without timestamps,
  so time cannot be located within the 143-, 158- and 67-second sessions. No session timed out, so
  nothing here needed attributing. A future timeout would be as unattributable as the preceding
  smoke's unless the instrument is changed to timestamp events; that change was outside this
  approval and was not made. Session-level times were accepted as meeting the approval; per-event
  timing would need an instrument change, which was not authorized.

Total host-reported cost was **$0.39468084**, below the approved $1.00 ceiling.

No instrument, runner, scorer, timeout, skill, policy or schema change was made.
